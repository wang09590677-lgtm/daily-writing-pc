## 0. 结论摘要（先看这里）

**根因（本轮精确定位）**：production `detectReps()` 每帧**重扫 d 的最近 0.35s 尾部**（`motion-engine.js:2653-2664`），尾部长度（21 帧）≈ 0.42× 周期；同一个 `+k` 平台在不同帧被反复"发现"，且期间夹着一个**陈旧**的 `-k` 样本重新 `armed` → **每周期计 2 次**。2× 的唯一成因是**重复处理陈旧样本**，不是 detrend 波形、不是 minRepGap、不是阈值。

**唯一能"在 12 动作 band 内全消 2×"的候选，只有"每样本只处理一次"这一类（F 家族）**：
- 候选 A1/A2/A3/A4/B/C/D/E —— 都**没能**全消（>1.5 的格子分别 8/0/7/15/15/13/12/11），或"消了 2× 但把真人计数也打没"。
- 候选 **F（单样本增量）/F′（居中延迟增量）** —— 12×5=60 格 **0 星**，且 band 内计数≈1.00（F）。这是"根因修法"。

**关键新发现（会改变需求③的判据，务必看第 5 节）**：**"现状真实视频 10/6/6/12/4" 这个基线本身就含 2×**。三法独立交叉（峰值法 / 单帧全局 / 团队几何周期）一致指向真值≈**开合跳 6~7 / 徒手深蹲 4~5 / 半蹲热身 5~6 / 跳绳 8 / 波比跳 2**。所以 ③"真实视频基本不变"**不能按字面执行**——一个**正确**的修复**本就应该**把跳绳 12→≈8、波比跳 4→≈2。F/F′ 在真实视频上的"下降"绝大部分是**纠偏**，不是回归。

**推荐排序**：

| 排名 | 方案 | 一句话 |
|---|---|---|
| 🥇 ① | **F 单样本增量**（`delay=0`） | 根因修法，改动最小、无新增失效模式；真实视频变化=纠偏（略欠计 1 次于开合跳/深蹲） |
| 🥈 ② | **F′ 居中延迟增量** | 真实视频真值吻合度最好，但**新引入"极慢动作 band 地板漏计为 0"**，需先加护栏 |
| 🥉 ③ | **F+B / F′+B** | 与 ①/② 等价；B（完整下-上）零收益、徒增状态机复杂度，不推荐 |
| ❌ | **A2 k=1.8rms** | 60 格 0 星是"假象"——它把真人动作也打到 0（真实视频 0/3/3/4/2），是最差的过度压制 |
| ❌ | A1/A3/A4/B/C/D/E | 均**未**全消 2×（残留 7~15 星），不符合① |

> ⚠️ 本报告只出**方案与数据**，**未改任何产品代码**；是否采纳、采纳哪个由 team-lead 决策。

## 1. 现状根因（复现 + 代码定位）

### 1.1 代码定位（`motion-engine.js` READ-ONLY）

```js
// detectReps()  (motion-engine.js:2573-2667)
const raw = signalWindow(key, 3.5);            // 3.5s 窗（motion-engine.js:2636）
if (raw.length < 10) return;
const spread = Math.max(...raw) - Math.min(...raw);
if (spread < gate) { st.armed = false; return; }   // 幅度闸门
const d = smooth(detrend(raw, win), smoothK);
const rms = Math.sqrt(mean(d.map(v => v*v))) || 1;
const k = clamp(rms*0.85, 0.45, 2.2);
const tail = Math.min(d.length, Math.max(2, Math.round(fps * 0.35)));  // ← 21 帧
for (let i = d.length - tail; i < d.length; i++) {   // ← 每帧重扫这 21 帧！
  const v = d[i];
  if (v < -k) st.armed = true;
  else if (v > k && st.armed) { /* count */ st.armed = false; }
}
```

- `win = clamp(round(fps*60/max(15,band[1])), 3, round(fps*1.5))`，60fps 下上限 = 90 帧 = 1.5s。
- `smoothK = max(1, round(fps*0.06))` = 4。
- `minGap = cfg("minRepGap")`。

### 1.2 复现证据（本会话）

| 方法 | 结果 |
|---|---|
| 单帧 `d`（整段一次 detrend）| **1 次/周期**（逻辑过零 1.29Hz 正确） |
| 逐帧滑窗复刻（=production）| **2 次/周期**（1.2Hz 时 86/36 = 2.39） |
| 计数时刻间隔 | 同一 0.833s 周期内两次计数，间隔 ≈0.4s（= 尾部长度） |

**结论**：多出来的那次，来自"重扫陈旧样本"——0.35s 尾部里存着上一半周期的 `-k`，下一帧再扫时它把 `armed` 打开，随即又扫到同一 `+k` 平台 → 二次计数。**把 `minGap` 调 0 也仍是 3Hz 1879 次**（说明不是 minGap 抑制、是真重复计数）。

## 6. 根因修法 F 的形态扫描（F vs F′）

F 家族是唯一"根因修法"，但形态不同，副作用不同：

| 变体 | ①星数/60 | ②band地板最低比值 | ③抗误计坏例 | ④真实偏差最大 | 真实 5 样本 reps |
|---|---|---|---|---|---|
| 现状 | 15 | 0.67 | 0 | 0 | 开合10/徒手6/半蹲6/跳绳12/波比4 |
| **F 延迟0（=F）** | **0** | **0.67**（=现状，无新增） | **0** | 6 | 开合5/徒手4/半蹲6/跳绳6/波比2 |
| **F′ 延迟half** | **0** | **0.00 ⚠️ 新增黑洞** | **0** | 4 | 开合7/徒手5/半蹲5/跳绳8/波比2 |
| F+win由band0 | 0 | 0.67 | 0 | 7 | 开合5/徒手4/半蹲6/跳绳5/波比2 |
| F′+win由band0 | 0 | 0.00 ⚠️ | 0 | 4 | 开合7/徒手5/半蹲6/跳绳8/波比2 |

（②"band地板最低比值"= 各动作在 band 最低拍速处的 引擎reps/物理周期，越接近 1.00 越好；0.67 是**现状也有**的慢速固有偏低，0.00 = **新黑洞**。）

### 6.1 F 与 F′ 的差异机制（已定位）

- **F（delay=0）**：每帧只处理"本帧新到的样本"。但该样本位于 detrend 窗的**最右端**（右半窗被裁剪）→ 存在**右边缘偏置**：局部均值偏移，使 `d` 幅度偏大。副作用：慢速动作反而"蒙对"（地板 0.67，同现状）；对快速动作（跳绳/开合/侧向跳）纠偏干净。
- **F′（delay=win/2）**：每样本延迟半窗、待其获得**居中窗**后处理。消除了右边缘偏置 → 真实视频真值吻合最好（开合 7 vs 真值 6~7、跳绳 8 vs 真值 8、波比 2 vs 真值 2）。**但**：当动作周期 ≫ win（如跪姿健腹轮 8/分 → 周期 7.5s，而 win=1.5s）时，居中 detrend 把信号削平到 `|d| < k面板 0.45` → **永不触发，计 0**（表 1 中 F′ 在 跪姿健腹轮 8/12/17、徒手深蹲 15、弓步蹲 12/18、半蹲热身 15 等低拍速格 = 0.00）。

> F′ 的黑洞在**真实视频里未暴露**（真实样本拍速都不在极端慢区），但**表 1 的合成慢速档暴露了**。若采纳 F′，**必须**加护栏（例如：给 win 设"不小于 ~1 个信号周期"的下限，或对极慢动作回退到 F/右端模式）。

## 7. 推荐排序 + 每个候选的回归风险面

### 🥇 ① F 单样本增量（`delay=0`）—— 首选

- 满足 ①：60/60 格 0 星，band 内计数≈1.00（0.89~1.09）。
- 满足 ②：抗误计全 0。
- 满足 ③：真实视频 5/4/6/6/2。**对照独立真值**（6~7/4~5/5~6/8/2）属**基本吻合**；开合跳少 1~2、徒手深蹲少 1（可接受的欠计，非 2× 残留）。
- 改动最小：只改"扫描哪些样本"（历史已处理下标 → 只处理新增样本），**不改**闸门/ detrend / k / minGap / getState 字段。
- **风险面**：真实慢速动作（跪姿健腹轮/死虫式）在极慢拍速下与现状同为偏低（0.67），**不是新增回归**。

### 🥈 ② F′ 居中延迟增量 —— 次选（须加护栏）

- 满足 ①：60/60 格 0 星（快速档 1.00）。
- 满足 ②：抗误计全 0。
- **真实视频真值吻合最好**：7/5/5/8/2（开合 7、跳绳 8、波比 2 三处与真值一致）。
- **风险面（新增失效模式）**：极慢动作 band 地板 **计 0**（周期 ≫ win 时居中 detrend 削平）。**未加护栏前不建议直接上线**。
- 需额外改动：缓冲 win/2 帧（延迟出数）+ win 下限护栏。

### 🥉 ③ F+B / F′+B —— 等价，但不推荐叠加 B

- 指标与 ①/② 完全相同；B（完整下-上状态机）**零收益**、徒增状态与迟滞路径复杂度。**不建议**。
